# 一、语言核心（01-JavaBasic）

## ① 封装 / 继承 / 多态

### A. 封装

**A1 访问控制**
- **Q**：`protected` 方法，不同包的子类能调用吗？`new Parent().m()` 呢？
  - **答**：子类**能**，但只能在**自己体内 / 通过子类实例**访问；`new Parent().m()` **编译报错**（限定类型必须是当前子类 S 或其子类）。
  - **变种**：「`protected` 和 `default` 跨包时差在哪？」｜「为什么 `this.m()` 能、`new Parent().m()` 不能？」
  - **追问**：若允许限定类型为 `Parent` 会怎样？（`protected` 退化成 `public`）
- **Q**：四种访问修饰符的可见范围？
  - **答**：private 本类 ｜ default 本类+同包 ｜ protected 本类+同包+子类 ｜ public 全部。
  - **变种**：「`protected` 能被**同包的无关类**访问吗？」（能）

**A2 可变性防御**
- **Q**：对象里有 `Date` 字段，外部能改到内部状态吗？怎么防？
  - **答**：能。**防御性拷贝**：构造时拷、返回时拷。
  - **变种**：「`final Date` 字段内部还会变吗？」（会，`final` 只锁引用）｜「什么时候**不用**防御性拷贝？」（字段本身不可变，如 `String`/`Integer`）
- **Q**：不可变对象要满足哪几个条件？
  - **答**：① 类 final ② 字段 final ③ 无修改方法 ④ 可变成员做拷贝。
  - **变种**：「`String` 为什么是不可变的？」
- **Q**：`record` 和普通类的区别？
  - **答**：自动 `private final` 字段 + 访问器 + `equals/hashCode/toString`，隐式 final；适合 DTO，不适合 JPA 实体。
  - **变种**：「`record` 能继承吗？」（不能）｜「能实现接口吗？」（能）

**A3 封装的性能误区**
- **Q**：getter 每次调用有性能开销吗？
  - **答**：无实质开销，JIT 会**内联**小方法。
  - **变种**：「什么情况 JIT 不内联？」（方法体 >325B、多态调用、递归）

### B. 继承

**B1 基础 + 初始化**
- **Q**：`new` 子类对象的构造器执行顺序？
  - **答**：**父先子后**（子类首行隐式 `super()`）：`Object` → 父 → 子。
  - **变种**：「不写 `super()` 会怎样？」（编译器自动加）
- **Q**：父类没有无参构造器，子类为什么编译报错？
  - **答**：子类隐式调 `super()` 找不到无参构造。解决：① 子类显式 `super(args)` ② 父类补无参构造器。
  - **变种**：「父类只写了带参构造器，子类还能编译吗？」
- **Q**：静态块、实例块、构造器执行顺序？
  - **答**：父静态块 → 子静态块 → 父实例块 → 父构造器 → 子实例块 → 子构造器。
  - **变种**：「静态块执行几次？」（一次）
- **Q**：一个类什么时候才会被初始化？
  - **答**：**首次主动使用**：`new`、访问静态成员、反射、子类初始化、`main` 类。被动引用不触发。
  - **变种**：「访问 `static final` 常量会触发初始化吗？」（**编译期常量不触发**）

**B2 重写规则**
- **Q**：重写有哪些规则？
  - **答**：① 名+参相同 ② 返回协变 ③ 权限不能更严 ④ 异常不能更宽 ⑤ `final`/`static`/`private` 不能重写。
  - **变种**：「返回类型能是父类吗？」（不行，只能相同或子类型）
- **Q**：`@Override` 不写行不行？
  - **答**：行。作用是**编译期检查**，建议都写。

**B3 构造器陷阱**
- **Q**：父类构造器调用被子类重写的方法，会怎样？
  - **答**：会调到**子类重写版**，但子类字段**还没初始化** → 拿到 `null`/默认值 → 可能 NPE。
  - **变种**：「构造器里调用可重写方法有什么风险？」｜「看代码，为什么抛 NPE？」（给父子类代码）
  - **追问**：若调用的是 `private`/`static` 方法，还会出问题吗？（不会，静态绑定）

**B4 继承 vs 组合**
- **Q**：什么时候用继承、什么时候用组合？
  - **答**：**is-a → 继承；has-a → 组合**；优先组合。
  - **变种**：「为什么说优先用组合？」（弱耦合、更灵活）
- **Q**：继承有什么缺点？举例。
  - **答**：**破坏封装**、父类改动波及子类、编译期绑定不灵活。例：`Stack extends Vector`。
  - **变种**：「`Stack extends Vector` 为什么是设计失误？」（能调 `add(index,e)` 破坏 LIFO）

### C. 多态

**C1 表现**
- **Q**：重载 vs 重写？分别在什么时候确定？
  - **答**：重载=编译期（静态绑定）；重写=运行期（动态绑定）。
  - **变种**：「为什么说重载是编译期多态、重写是运行期多态？」
- **Q**：向上 / 向下转型？
  - **答**：向上安全；向下需 `instanceof`，否则 `ClassCastException`。
  - **变种**：「`instanceof` 模式匹配（Java16）怎么写？」

**C2 底层机制**
- **Q**：`a.sound()` 运行时怎么找到要执行的方法？
  - **答**：**动态分派**：引用→实际对象→对象头→类元信息→**虚方法表**→方法入口→执行。
  - **变种**：「运行时多态的实现原理是什么？」
- **Q**：虚方法表是什么？存哪？
  - **答**：每类一张，存在**方法区**；子类表复制父类表 + 覆盖重写 + 追加新方法；接口用 itable。
  - **变种**：「字段访问走虚方法表吗？」（不走）

**C3 绑定时机**
- **Q**：父类引用指向子类对象，`o.x` 和 `o.getX()` 输出什么？
  - **答**：`o.x` 取**父类值**（字段静态绑定）；`o.getX()` 取**子类值**（方法动态绑定）。
  - **变种**：「为什么字段没有多态？」
- **Q**：静态方法 / `private` 能重写吗？
  - **答**：都不能。静态方法叫**隐藏**（按引用类型调）；`private` 不可见。
  - **变种**：「静态方法被"隐藏"后，按什么类型调用？」（引用类型）

**C4 易错 + 应用**
- **Q**：`null` 传给重载方法，调哪个？
  - **答**：调**最具体**的（继承层次最低）；同样具体则**编译报错**（歧义）。
  - **变种**：「`f(Object)` 和 `f(String)` 传 `null`，调哪个？」（`String`）
- **Q**：基本类型 / 包装类型重载怎么选？
  - **答**：编译期按"最匹配"选，可能触发装箱/拆箱，结果可能非你所想。
  - **变种**：「`f(long)` 和 `f(Integer)` 传 `int` 走哪个？」
- **Q**：项目里哪里用到多态？
  - **答**：策略模式、模板方法、工厂方法。
  - **变种**：「策略模式怎么体现多态？」「你项目有没有类似场景？」

## ② `equals` 与 `hashCode`

**点1 契约**
- **Q**：`equals` 和 `hashCode` 的契约？
  - **答**：`equals` 相等 → `hashCode` **必等**；`hashCode` 等**不要求** `equals` 等；重写 `equals` **必须**重写 `hashCode`。
  - **变种**：「为什么重写 `equals` 必须重写 `hashCode`？」｜「`equals` 相等，`hashCode` 一定相等吗？反过来呢？」
- **Q**：只重写 `equals` 不重写 `hashCode` 会怎样？
  - **答**：两个"逻辑相等"对象落在**不同桶** → `get` 找不到、`Set` 出现重复。
  - **变种**：「`HashSet` 里放两个 `equals` 相等但没重写 `hashCode` 的对象，size 是多少？」（2）

**点2 性质**
- **Q**：`equals` 要满足哪几条性质？
  - **答**：自反、对称、传递、一致性、与 `null` 返回 `false`。
  - **变种**：「违反对称性会发生什么？」

**点3 集合中的坑**
- **Q**：用可变对象当 `HashMap` 的 key？
  - **答**：改到影响 `hashCode` 的字段后，**定位不到原桶**，`get` 失效。
  - **变种**：「`HashMap` 里两步定位是怎样的？」（先 hash 定位桶，再 `equals`）
- **Q**：`HashSet` 怎么判重？
  - **答**：先 `hashCode` 定位，再 `equals` 比内容。

**点4 实践**
- **Q**：`String.equals` 怎么实现？为什么先比引用？
  - **答**：先 `==`（同一对象直接 true，快路径），再比长度和字符。
  - **变种**：「`Objects.equals` 和 `a.equals(b)` 区别？」（前者防空指针）
- **Q**：`hashCode` 常用 31 做乘数？
  - **答**：31 是奇素数，`31*i` 可优化为移位减法，分布较好。
  - **变种**：「`Object` 默认 `hashCode` 是什么？」（对象地址派生）

## ③ `String` 不可变与常量池

**点1 不可变**
- **Q**：`String` 为什么不可变？好处？
  - **答**：类 final、`value` final、无修改方法。好处：常量池安全复用、线程安全、可做 key、类加载安全。
  - **变种**：「不可变的"三层含义"？」
- **Q**：不可变带来哪些好处？
  - **答**：见上。

**点2 对象个数**
- **Q**：`new String("abc")` 创建几个对象？
  - **答**：池中无 → 入池(1)+`new`(1) = **2**；池中已有 → **1**。
  - **变种**：「`String s = "a" + "b" + "c"` 创建几个？」（编译期折叠为 `"abc"`，0~1 个）

**点3 常量池 / intern**
- **Q**：字符串常量池在哪？`intern()` 做什么？
  - **答**：JDK7 起在**堆**；`intern()`：有则返池中引用，无则入池返回。
  - **变种**：「`intern()` 和直接赋字面量有什么区别？」
- **Q**：JDK7 前后常量池位置变化？
  - **答**：JDK6 永久代 → JDK7+ 堆。

**点4 JDK9 优化**
- **Q**：JDK9 为什么 `char[]` → `byte[]`？
  - **答**：加 `coder` 区分 Latin-1/UTF-16，ASCII 省一半内存。
  - **变种**：「`String` 的内存占用怎么算？」

**点5 边界**
- **Q**：反射能改 `String` 的值吗？
  - **答**：能（`setAccessible` 改内部数组），属暴力破坏，JDK17 受限。

## ④ Java 值传递

**点1 结论**
- **Q**：Java 是值传递还是引用传递？
  - **答**：**只有值传递**；传对象时传的是**引用的副本**。
  - **变种**：「为什么说 Java 没有引用传递？」

**点2 影响**
- **Q**：方法里改对象参数影响外部吗？
  - **答**：改**内部状态**会（同一对象）；**重新赋值**（换引用）不会。`String` 不变，`StringBuilder` 会变。
  - **变种**：「`String` 传进方法里改了，外面为什么没变？」

**点3 陷阱**
- **Q**：`swap` 方法能交换两个对象吗？
  - **答**：不能，交换的是引用副本。
  - **变种**：「怎么才能"交换"？（返回新引用 / 封装容器）」

## ⑤ 类的初始化时机与对象初始化顺序

**点1 初始化时机**
- **Q**：类什么时候被初始化？
  - **答**：首次**主动使用**（`new`、访问静态成员、反射、子类初始化、`main`）。
  - **变种**：「被动引用会触发吗？」「常量会触发吗？」

**点2 初始化顺序**
- **Q**：`new` 对象的初始化顺序？
  - **答**：父静态块 → 子静态块 → 父实例块 → 父构造器 → 子实例块 → 子构造器。
  - **变种**：「字段初始化和构造器谁先？」（字段初始化在构造器之前）

**点3 静态 vs 实例**
- **Q**：静态块什么时候执行？几次？
  - **答**：类初始化时，一次。

## ⑥ `Integer` 缓存池与装箱拆箱

**点1 缓存**
- **Q**：`a=127,b=127; a==b`？128 呢？
  - **答**：127 → **true**；128 → **false**（缓存 -128~127）。
  - **变种**：「哪些包装类有缓存？」（Byte/Short/Integer/Long 有，Float/Double 无）
- **Q**：缓存范围能调吗？
  - **答**：`-XX:AutoBoxCacheMax` 调上界。

**点2 拆箱的坑**
- **Q**：自动拆箱在哪引发 NPE？
  - **答**：包装类型为 `null` 时参与运算/比较/赋值给基本类型。
  - **变种**：「三元表达式混用基本/包装会怎样？」（类型统一并拆箱，可能 NPE）

**点3 创建方式**
- **Q**：`new Integer(1)` vs `Integer.valueOf(1)`？
  - **答**：前者强制新对象，后者走缓存。

## ⑦ 泛型

**点1 类型擦除**
- **Q**：什么是类型擦除？为什么擦除？
  - **答**：编译后擦成 `Object` 或上界，运行期无泛型；为了**向后兼容**。
  - **变种**：「`List<String>` 和 `List<Integer>` 运行时是同一个类吗？」（是）
- **Q**：擦除的坑（举 3 个）？
  - **答**：不能 `new T()`/`new T[]`、不能 `instanceof T`、静态字段不能依赖类型参数。

**点2 桥接方法**
- **Q**：什么是桥接方法？
  - **答**：编译器为保持多态生成的合成方法（如 `compareTo(Object)` 桥接到 `compareTo(Integer)`）。
  - **变种**：「为什么需要桥接方法？」（擦除后多态会断）

**点3 通配符**
- **Q**：`? extends` vs `? super`？PECS？
  - **答**：`extends` 只读、`super` 只写；**PECS = Producer Extends, Consumer Super**。
  - **变种**：「`List<? extends Number>` 能 `add` 吗？」（不能）

**点4 限制**
- **Q**：泛型有哪些限制？
  - **答**：不支持基本类型、不能 `new T()`、不能 `instanceof T`、不能泛型数组。
  - **变种**：「什么是堆污染？`@SafeVarargs` 干嘛的？」

## ⑧ 异常体系与 `finally`

**点1 分类**
- **Q**：受检异常 vs 运行时异常？
  - **答**：受检必须处理；运行时（`RuntimeException`）不强制；`Error` 一般不处理。
  - **变种**：「什么时候该自定义受检异常？」

**点2 finally 陷阱**
- **Q**：`finally` 里写 `return`？
  - **答**：**吞掉** `try` 的 return 和异常，不建议。
  - **变种**：「`finally` 里抛异常会怎样？」（覆盖原异常）
- **Q**：`try` `return`、`finally` 改值？
  - **答**：返回值在 `return` 时已确定；改局部变量不影响返回值。

**点3 资源关闭**
- **Q**：`try-with-resources` 原理？关闭顺序？
  - **答**：资源实现 `AutoCloseable`，自动关闭；**逆序关闭**；异常被抑制（suppressed）。
  - **变种**：「它和 `finally` 里 `close` 比好在哪？」（异常抑制、更简洁）

**点4 实践**
- **Q**：自定义异常怎么设计？异常链？
  - **答**：可恢复→受检，编程错误→运行时；`initCause`/构造器传 `cause` 形成异常链。

## ⑨ 浮点数与 `BigDecimal`

**点1 精度**
- **Q**：`0.1 + 0.2 == 0.3` 吗？
  - **答**：**不等于**，结果 ≈ `0.30000000000000004`。
  - **变种**：「为什么浮点数会有精度问题？」（二进制无法精确表示）

**点2 金额**
- **Q**：金额为什么不用 `double`？
  - **答**：精度误差；用 **`BigDecimal`**（构造传 `String`）。
  - **变种**：「`new BigDecimal(0.1)` 有什么问题？」（传 double 会引入误差，用 `"0.1"`）

**点3 BigDecimal 陷阱**
- **Q**：`equals` vs `compareTo`？
  - **答**：`equals` 比**值和精度**（`1.0≠1.00`）；`compareTo` 只比**数值**。判等用 `compareTo`。
  - **变种**：「`BigDecimal` 除法要注意什么？」（指定精度 + 舍入模式，否则 `ArithmeticException`）

# 二、集合（02-JavaCollect）

## ⑩ `HashMap`

**点1 结构**
- **Q**：底层数据结构？JDK8 有什么变化？
  - **答**：数组 + 链表；JDK8 链表长度 ≥8 且数组 ≥64 时转**红黑树**，≤6 退化。
  - **变种**：「为什么树化阈值是 8？」｜「为什么数组小于 64 时先扩容而不是树化？」
- **Q**：`put` 的过程？
  - **答**：算 hash 定位桶 → 空则放；非空比 hash/equals，相同则覆盖，不同则尾插（JDK8）；超阈值树化；`++size` 超阈值扩容。
  - **变种**：「JDK7 头插、JDK8 尾插有什么区别？」（头插并发扩容易成环）

**点2 扩容**
- **Q**：什么时候扩容？机制？
  - **答**：`size > 容量 × 0.75` 时扩容 2 倍；rehash 时元素**要么留原桶、要么移到"原索引 + 旧容量"**。
  - **变种**：「为什么负载因子是 0.75？」（空间与冲突折中）
- **Q**：为什么容量必须是 2 的幂？
  - **答**：`(n-1) & hash` 等价取模且更快、分布均匀。

**点3 扰动**
- **Q**：为什么对 hash 做 `h ^ (h >>> 16)`？
  - **答**：让**高位也参与**索引运算，减少冲突。

**点4 红黑树**
- **Q**：树化 / 退化阈值？
  - **答**：链表 ≥8 且容量 ≥64 转树；树 ≤6 退化链表。

**点5 线程安全**
- **Q**：`HashMap` 线程安全吗？
  - **答**：不安全；JDK7 并发扩容可能**成环**（死循环），JDK8 可能丢数据。

## ⑪ `ConcurrentHashMap`

**点1 结构演进**
- **Q**：JDK7 和 JDK8 的实现差异？
  - **答**：JDK7 **分段锁 Segment**（继承 `ReentrantLock`）；JDK8 **取消分段**，用 **CAS + synchronized 锁单个桶头**。
  - **变种**：「JDK8 为什么放弃分段锁？」（粒度更细、并发更高）
- **Q**：JDK8 怎么保证线程安全？
  - **答**：空桶 CAS 插入；非空桶 `synchronized` 锁头节点；扩容时多线程**协助迁移**。

**点2 细节**
- **Q**：为什么不允许 key / value 为 `null`？
  - **答**：并发下 `get` 返回 `null` **无法区分**"key 不存在"和"value 为 null"；`HashMap` 单线程可用 `containsKey` 消歧。
- **Q**：`size` 怎么统计？
  - **答**：`baseCount` + `CounterCell[]` 分散计数（类 LongAdder）。
- **Q**：扩容时其他线程在干嘛？
  - **答**：`helpTransfer` 协助搬迁。

---

## ⑫ fail-fast 与集合选型

**点1 fail-fast**
- **Q**：for-each 里删元素为什么抛 `ConcurrentModificationException`？
  - **答**：迭代器用 `modCount` 校验结构是否被改，被改即抛（**fail-fast**）。
  - **变种**：「怎么正确地在遍历中删除？」（`iterator.remove()` / `removeIf`）

**点2 选型**
- **Q**：`ArrayList` vs `LinkedList`？
  - **答**：ArrayList 数组、随机访问 O(1)、中间插删 O(n)（要挪动）；LinkedList 双向链表、头尾 O(1)、随机访问 O(n)、内存开销大。
  - **变种**：「为什么实际更常用 ArrayList？」（CPU 缓存友好）
- **Q**：`CopyOnWriteArrayList`？
  - **答**：写时复制新数组、读无锁；适合**读多写少**。
- **Q**：`LinkedHashMap` 怎么实现 LRU？
  - **答**：`accessOrder=true` + 重写 `removeEldestEntry`。

# 三、并发（03-JavaConcurrent）

## ⑬ `synchronized`

**点1 原理**
- **Q**：原理是什么？锁存在哪？
  - **答**：`monitorenter` / `monitorexit`；锁信息在**对象头 Mark Word**，关联 ObjectMonitor。
  - **变种**：「`monitorenter` 和 `monitorexit` 成对吗？」（异常路径有隐式 exit，保证释放）
- **Q**：锁升级过程？
  - **答**：无锁 → **偏向锁** → **轻量级锁**（CAS 自旋）→ **重量级锁**（OS 互斥）。
  - **变种**：「偏向锁为什么在 JDK15 后默认关闭？」（撤销成本高）

**点2 细节**
- **Q**：`synchronized` vs `ReentrantLock`？
  - **答**：synchronized 是 JVM 关键字、自动释放、非公平；ReentrantLock 是 API，可**中断/超时/公平/多条件**。
- **Q**：对象头里存了什么？
  - **答**：Mark Word（hash、GC 分代年龄、锁标志、偏向线程 ID 等）+ 类型指针。
- **Q**：`synchronized` 保证什么？
  - **答**：原子性、可见性、有序性。

---

## ⑭ `volatile` 与 JMM

**点1 volatile**
- **Q**：`volatile` 的作用？
  - **答**：保证**可见性** + **禁止指令重排**；**不保证原子性**。
  - **变种**：「`volatile` 底层怎么实现的？」（内存屏障）
- **Q**：能保证原子性吗？为什么 `i++` 不行？
  - **答**：不能。`i++` 是"读-改-写"三步，非原子，需 `AtomicInteger`/锁。

**点2 JMM**
- **Q**：JMM 是什么？主内存 / 工作内存？
  - **答**：抽象内存模型；每个线程有**工作内存**（副本），读写需与**主内存**同步。
  - **变种**：「JMM 和 JVM 运行时内存结构是一回事吗？」（不是）
- **Q**：什么是 happens-before？
  - **答**：定义可见性的偏序：程序顺序、监视器锁、volatile、线程启动/终止、传递性。
- **Q**：指令重排？`volatile` 怎么禁？
  - **答**：编译器/CPU 为性能重排；`volatile` 通过**内存屏障**（LoadLoad / StoreStore 等）禁止。

---

## ⑮ CAS 与原子类

**点1 CAS**
- **Q**：什么是 CAS？哪三个问题？
  - **答**：比较并交换（`Unsafe`，底层 CPU `cmpxchg`）；问题：① **ABA** ② **自旋开销** ③ 只能保证**单个变量**原子。
  - **变种**：「CAS 怎么解决 ABA？」（版本号 `AtomicStampedReference`）
- **Q**：ABA 问题？
  - **答**：值 A→B→A，CAS 察觉不到；用**版本号 / 时间戳**解决。

**点2 原子类**
- **Q**：`AtomicInteger` 怎么实现原子操作？
  - **答**：`volatile value` + CAS 循环重试。
- **Q**：`LongAdder` 快在哪？
  - **答**：**分段累加**（Cell 数组）减少 CAS 竞争，最后 `sum`。

---

## ⑯ AQS

**点1 核心**
- **Q**：AQS 的原理？`state` 和队列的作用？
  - **答**：`volatile int state` + **CLH 变体双向等待队列**；模板方法 `acquire`/`release`，子类实现 `tryAcquire` 等。
  - **变种**：「`state` 的具体含义由谁定？」（由子类定义，如锁重入次数）
- **Q**：独占模式 vs 共享模式？
  - **答**：独占同一时刻一个线程（ReentrantLock）；共享多个（Semaphore、CountDownLatch）。

**点2 应用**
- **Q**：`ReentrantLock` / `Semaphore` / `CountDownLatch` 怎么用 AQS？
  - **答**：分别实现 `tryAcquire/tryRelease`（独占）与 `tryAcquireShared/tryReleaseShared`（共享），`state` 含义不同。
- **Q**：`Condition` 等待队列？
  - **答**：AQS 内部 `ConditionObject`；`await` 入条件队列，`signal` 转移到同步队列。

---

## ⑰ `ReentrantLock`

**点1 特性**
- **Q**：公平锁和非公平锁的区别？
  - **答**：公平按 FIFO（`hasQueuedPredecessors`）；非公平允许插队、吞吐更高。**默认非公平**。
  - **变种**：「为什么不公平反而更快？」（减少唤醒阻塞切换开销）
- **Q**：`ReentrantLock` vs `synchronized` 怎么选？
  - **答**：需要可中断/超时/公平/多条件 → ReentrantLock；否则优先 synchronized（简洁、不易漏释放）。
- **Q**：可重入怎么实现？
  - **答**：`state` 计数，同线程再次获取 +1，释放 -1，归 0 才真正释放。

---

## ⑱ 线程池

**点1 执行流程**
- **Q**：核心参数有哪些？执行流程？
  - **答**：`corePoolSize`、`maximumPoolSize`、`keepAliveTime`、`unit`、`workQueue`、`threadFactory`、`handler`；流程 **core → 队列 → max → 拒绝**。
  - **变种**：「任务来了先建线程还是先入队？」（先建到 core，满了入队）
- **Q**：拒绝策略有哪几种？
  - **答**：Abort（抛异常，默认）、CallerRuns、Discard、DiscardOldest。

**点2 参数设计**
- **Q**：核心线程数怎么设？
  - **答**：CPU 密集 ≈ **N+1**；IO 密集 ≈ **2N** 或 (1 + 等待/计算) × N，再压测微调。
- **Q**：为什么不用 `Executors`？
  - **答**：`FixedThreadPool`/`SingleThread` 用**无界队列** → OOM；`CachedThreadPool` 最大线程 `Integer.MAX_VALUE` → 线程爆炸。

**点3 细节**
- **Q**：线程怎么复用？空闲怎么回收？
  - **答**：worker 循环 `getTask()` 取任务；非核心线程超 `keepAliveTime` 回收。
- **Q**：线程池异常怎么处理？
  - **答**：`submit` 会**吞异常**（需 `Future.get`）；`execute` 交由未捕获异常处理器；建议任务内 try-catch。

---

## ⑲ `ThreadLocal`

**点1 原理**
- **Q**：`ThreadLocal` 的原理？
  - **答**：每个 `Thread` 持有 `ThreadLocalMap`，key 是 ThreadLocal（**弱引用**）、value 是值；`set/get` 操作当前线程的 map。
- **Q**：为什么会内存泄漏？怎么避免？
  - **答**：key 弱引用被 GC 后，value 仍被 Entry **强引用**，线程存活则泄漏；**用完 `remove()`**。

**点2 细节**
- **Q**：key 为什么用弱引用？
  - **答**：让 ThreadLocal 对象可被回收，减少泄漏。
- **Q**：`InheritableThreadLocal`？
  - **答**：子线程可继承父线程的值（创建时复制）。

---

# 四、JVM（04-JavaJVM）

## ⑳ 运行时内存区域

- **Q**：JVM 运行时内存分哪几块？
  - **答**：线程私有：**程序计数器、虚拟机栈、本地方法栈**；线程共享：**堆、方法区（元空间）**；另有直接内存。
  - **变种**：「哪些线程共享、哪些私有？」
- **Q**：堆和栈的区别？栈帧里有什么？
  - **答**：栈存**局部变量表、操作数栈、动态链接、返回地址**；堆存对象实例。
  - **变种**：「一个方法调用对应几个栈帧？」
- **Q**：JDK8 为什么用元空间替代永久代？
  - **答**：永久代在堆内、难调、易 OOM；元空间用**本地内存**，更灵活。
- **Q**：对象的创建过程？
  - **答**：类加载检查 → 分配内存（指针碰撞/空闲列表）→ 零值 → 设对象头 → 执行构造器。

---

## ㉑ 垃圾判定与引用类型

- **Q**：怎么判断对象可回收？
  - **答**：**可达性分析**，从 GC Roots（栈引用、静态变量、常量、JNI）不可达即回收。
  - **变种**：「为什么不用引用计数？」（循环引用无法回收）
- **Q**：四种引用分别有什么用？
  - **答**：**强**（不回收）、**软**（内存不足回收，做缓存）、**弱**（下次 GC 回收）、**虚**（回收通知，管理直接内存）。

---

## ㉒ 分代与收集器

- **Q**：为什么分代？新生代怎么工作？
  - **答**：多数对象**朝生夕死**；Eden + 2 Survivor，Minor GC 复制存活对象到 Survivor，年龄递增。
  - **变种**：「为什么用复制算法？」（新生代存活少，效率高）
- **Q**：常见收集器？CMS 和 G1 的区别？
  - **答**：Serial/ParNew/Parallel/CMS/G1/ZGC；CMS 分代 + 并发标记清除（有碎片）；G1 分区（Region）+ 可预测停顿。
  - **变种**：「JDK9 起默认收集器是？」（G1）
- **Q**：对象什么时候进老年代？
  - **答**：年龄到阈值（默认 15）、大对象、Survivor 放不下、动态年龄判断。
- **Q**：Minor / Full GC 何时触发？
  - **答**：Minor：Eden 满；Full：老年代满、元空间满、`System.gc`、并发失败等。

---

## ㉓ G1

- **Q**：G1 的原理？
  - **答**：堆分为多个 **Region**（逻辑分代）；可设 `MaxGCPauseMillis`；**并发标记** + 优先回收垃圾多的 Region；用 **Remembered Set** 处理跨代引用。
  - **变种**：「G1 怎么做到可预测停顿？」（按 Region 收益排序、控制回收数量）
- **Q**：相比 CMS 有什么优势？
  - **答**：可预测停顿、**无内存碎片**（复制整理）、Region 化。
- **Q**：回收过程？
  - **答**：Young GC → Mixed GC（含部分老年代）→ Full GC（兜底）。

---

## ㉔ 类加载与双亲委派

- **Q**：类加载的过程有哪几步？
  - **答**：加载 → 验证 → 准备 → 解析 → 初始化（+ 使用、卸载）。
  - **变种**：「准备阶段和初始化阶段分别做什么？」（准备赋默认值，初始化执行 `<clinit>`）
- **Q**：什么是双亲委派？为什么需要它？
  - **答**：加载请求先交给父加载器；保证**核心类不被篡改**、**避免重复加载**。
- **Q**：怎么打破双亲委派？
  - **答**：重写 `loadClass`；SPI 用**线程上下文类加载器**；Tomcat（WebappClassLoader 优先本地）；OSGi。
- **Q**：有哪些类加载器？
  - **答**：Bootstrap、Extension/Platform、Application、自定义。

---

## ㉕ OOM 与调优

- **Q**：常见 OOM 有哪些？
  - **答**：堆内存溢出、GC overhead、元空间、直接内存、栈溢出（StackOverflowError）。
  - **变种**：「`OutOfMemoryError: Metaspace` 一般是什么原因？」（类加载过多）
- **Q**：线上 CPU 飙高 / 内存泄漏怎么定位？
  - **答**：`top -Hp` 找线程 → `jstack` 看栈；内存用 `jmap -dump` + **MAT** 分析。
  - **变种**：「死循环和锁竞争导致的 CPU 高，栈有什么区别？」
- **Q**：常用调优参数？
  - **答**：`-Xms/-Xmx`、`-Xmn`、`-XX:MetaspaceSize`、`-XX:+UseG1GC`、GC 日志等。
- **Q**：用过哪些工具？
  - **答**：`jps/jstat/jstack/jmap/jinfo`、**Arthas**、MAT。

---

# 五、新特性（05-JavaNewFeatures）— P1

## ㉖ Lambda / Stream

- **Q**：Lambda 的本质是什么？什么是函数式接口？
  - **答**：Lambda 是**函数式接口**（仅一个抽象方法）的实例；编译为 `invokedynamic` + 合成方法。
  - **变种**：「`@FunctionalInterface` 有什么用？」（编译期校验只有一个抽象方法）
- **Q**：Stream 的惰性求值是什么意思？并行流有什么坑？
  - **答**：中间操作**惰性**，遇到终端操作才执行；并行流**共享可变状态不安全**、默认共用 ForkJoinPool 可能拖垮其他任务。

---

## ㉗ Optional 与现代特性

- **Q**：`Optional` 怎么正确使用？
  - **答**：用于**返回值**表达"可能为空"；用 `orElse/getOrElse/map/ifPresent`；**别用 `get()`**。
  - **变种**：「`orElse` 和 `orElseGet` 的区别？」（前者总会执行，后者惰性）
- **Q**：`record` / `sealed` / 模式匹配解决什么问题？
  - **答**：`record` 不可变数据载体；`sealed` 限制继承范围；模式匹配简化 `instanceof`/`switch` 的类型判断与解构。
